# V02/V03 — JWT implementation and OIDC claim repair

AI-assisted implementation, tests and documentation; external implementation code
copied: none. Implemented on the development branch; pending CI/lead review.

Replaced python-jose 3.5.0 with PyJWT[crypto] 2.15.1. The revised runtime and dev
manifest audit resolves without known findings; python-jose and its ecdsa/rsa
chain are absent. Removed the obsolete ECDSA advisory ignore from CI and included
the developer manifest. No new suppression or severity relaxation was added.

Before migration, four independent signed-ID-token regressions failed because
missing exp/aud/sub/iat was accepted. They now pass. OIDC validates required issuer,
audience, expiry, integer issue/expiry times, nonempty string subject, bound nonce,
RSA-only algorithms and exactly one matching kid in the provider's JWKS. Key use,
algorithm and verification operations are checked; token headers never initiate
key/network retrieval. Multiple audiences require the matching authorized party.
Malformed/expired/wrong-key/DER-HMAC tokens normalize to the existing SSO error.

Production internal JWT configuration permits HS256/384/512 with at least
32/48/64 bytes respectively for active and every fallback key. Length cannot prove
randomness: generate keys with a cryptographic generator and store them as secrets.
Existing weak production keys must be replaced before rollout; do not load them as
fallbacks. That exceptional rotation invalidates sessions and outstanding SSO
attempts. Strong HS256 keys can rotate normally: new active, old verify-only fallback
for the session lifetime, then remove. No real deployment secrets were inspected.
Internal access/state contracts keep their separate audience/claim requirements.
An independent HMAC wire encoder verifies legacy valid HS256 fallback compatibility.
No schema/data migration; valid strong-key sessions need no forced logout.

Identity trust remains the admin-configured organization IdP and allowed-domain
policy. Email is required as a string; an explicit email_verified=false is rejected.
IdPs omitting email_verified remain trusted to assert the address. This does not
certify live IdP ownership/account-linking policy; live enterprise acceptance is
still in the decision register. There is no outbound email/provider call in tests.

Validation: 158 auth/session/SSO/browser-binding/SCIM/tenant regression tests passed,
1 optional test skipped. A final overlapping claims/config group passed 72 tests,
including added malformed identity cases; these counts are not additive. Whole-app
mypy passed (414 files), Ruff lint/format and dependency consistency passed. The
fresh pip-audit 2.10.1 result is zero findings for runtime + developer manifests.
PostgreSQL and full-head CI remain required before merge; no deployment performed.

Rollback must preserve the required-claim/key policy and use a tested non-vulnerable
implementation. Do not treat reinstalling python-jose/ecdsa or weak-key fallback as
a security-cleared rollback. Main remains unchanged and PR #62 remains draft.
