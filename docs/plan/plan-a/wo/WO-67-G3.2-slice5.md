### Objective and business value

Verified at HEAD=`184fb52`: `fuel_card_parser._default_parsers()`
registers exactly `[EurowagParser(), E100Parser(), Q8Parser(),
DKVParser()]`; no TFC parser exists, so a TFC by Moya statement has no
path into the claim engine at all (`select()` raises
`unrecognized_fuel_card_statement`). `BA_fleet_fuel.md` §5.1's TFC row
(line 1100) gives the network's harvested quirks verbatim: *"UAB
«Client-LT-3»; EUR; monthly; −0.205/L **only at TFC hubs** (Meer −0.19);
third-party stations undiscounted. Flat 21% VAT."* — and §4.2 (line
1011) classifies that hub discount as **ON-INVOICE** ("already inside
`net_eur`"). This is a FOURTH distinct money model — the DERIVED-NET
model: where Eurowag/Q8 read three independently-given figures, E100
reverse-calculates from a VAT-inclusive gross, and DKV trusts a
supplier-stated EUR, a TFC statement prices each line as litres × a LIST
price and the invoiced net is what remains after the per-litre,
station-classified hub discount, with the VAT derived at the one flat
21% rate. WO-62's own slice list said it first: TFC "needs a
station-classification concept this order's Eurowag parser has no
equivalent of". All of that arithmetic is parser-local: the derived
`net_local`/`vat_local`/`gross_local` ride the EXISTING `ParsedFuelLine`
fields, and every line is EUR so ingestion's untouched identity branch
applies — the shared contract does not change (WO-65's stability
argument, honored by construction).

Who stops losing money: every TFC statement for the «Client-LT-3»-shaped
Lithuanian entity currently has NO path to a VAT claim — unrecoverable
foreign VAT for any fleet fueling on the TFC/Moya network. Worse, a
naive port that ignored the station classification would price hub
fillings at LIST (overstating net and the 21% VAT on it — a wrong figure
feeding a legal filing) or discount third-party fillings that were never
discounted (understating the claim). The tier constants and the flat
rate are the harvested contract; deriving them deterministically per
line — and refusing any row whose classification is unknown rather than
guessing a discount — is exactly the "every promise dies if a number is
wrong" discipline. And because WO-66's gate + tie-out are now live, this
network is the first proven against the real onboarding contract: the
€0.02/€0.03 coversheet tie-out runs over TFC's DERIVED figures through
`ingest_statement` itself.

### Implementation guidance

1. **The derived-net money model (the reason this slice exists).** The
   harvested facts are the tier constants (−0.205/L hub, −0.19/L Meer,
   0 third-party), the flat 21% VAT, the EUR currency, and that the
   discount is ON-INVOICE (inside the invoiced net — §4.2). Everything
   else is a DOCUMENTED INTERPRETATION flagged in the module docstring
   (no worked TFC column layout exists in the spec — the same
   discipline as every prior parser's shape choice): the statement
   prints the LIST unit price plus a per-line station classification,
   and the parser derives the invoiced figures. All arithmetic is pure
   `Decimal`, UNROUNDED in the returned `ParsedFuelLine` —
   `fuel_ingest.ingest_transaction` stays the one place that `q2`s
   (WO-50's convention). Numeric identity to prove in tests:
   `net_local + vat_local == gross_local` exactly (pre-rounding), and
   `vat_local / net_local == 21%` exactly — which is also why rule 9 of
   the WO-66 gate stays coherent for BE/NL/LT lines.
2. **The station-classification concept fails CLOSED.** `station_class`
   is normalized case-insensitively to one of `hub` / `meer` /
   `third_party`; ANY other value is a malformed row that aborts the
   whole statement. A guessed tier is an invented discount — the exact
   failure mode `select()`'s fail-closed network detection exists to
   prevent, one level down. Same for a non-EUR row (the EUR/L tier
   constants cannot be applied to another currency) and a non-positive
   discounted unit price (a hub row with `list_price_eur_l <= 0.205`
   is a mis-keyed price; refuse it HERE with the real defect named,
   not downstream as a review-gate `net_not_positive` on a figure the
   operator never typed).
3. **The WO-66 gate is upstream of ingestion now — fixtures must pass
   it.** Every factory row carries an `invoice_ref` (gate rule 1,
   error), and the default fixture's countries are BE/NL (21% standard
   — rule 9 coherent by construction since the parser derives VAT at
   exactly 21%). The ingest suite must include the live-gate
   onboarding pair over DERIVED figures: with explicit rows summing to
   an unrounded `Σ(net+vat)` = 761.695 (hub 100 L × 1.500; meer 200 L
   × 1.490; third_party 150 L × 1.600), `q2` = 761.70 — a coversheet
   of 761.72 registers (diff €0.02) and 761.73 blocks
   (`capture_review_blocked`, zero rows). This is §5.1's "PASS =
   trained" run against the real gate for the first time.
4. **No entity detection, ever, for TFC.** Mirror `q8.py`/`dkv.py`
   exactly: no scan exists in the module; `entities` is unconditionally
   `[]`; ONE warning per parse using the "not implemented for this
   network" wording; an adversarial test plants a "TFC by Moya ...
   VAT: LT..."-shaped decoy line and asserts `entities` stays empty.
5. **Registration + the one alignment.** `_default_parsers()` appends
   `TFCParser()` fifth. Five distinct literal first-line markers ⇒
   registration order remains provably irrelevant. The DKV suite's
   exact-four-list registry test is aligned to membership + relative
   order (comment pointing at this order, mirroring the WO-65 comment
   in `test_g3_2_q8_fuel_card_parser.py`); the exact five-list is
   asserted in the TFC suite. Every OTHER WO-62..66 test passes
   byte-for-byte unmodified.

### Invariants this order must preserve

- **§4.9 (Decimal, never float)** — the tier constants, the derivation
  and the flat-rate VAT are pure `Decimal`; the ONE rounding point
  stays `ingest_transaction.q2`.
- **§4.10 (the server recomputes every total)** — genuinely SATISFIED
  here, not excepted: the parser recomputes the invoiced net from the
  printed price, classification and litres using the harvested contract
  constants; nothing client-supplied is trusted as a total.
- **§4.14/§4.15 (one FX convention)** — untouched by construction:
  every TFC line is EUR (enforced fail-closed) and rides the existing
  identity branch; no FX code changes.
- **§4.19 (R25 gate semantics)** — the WO-66 gate is not modified; this
  order only proves a NEW network's fixtures against it (the €0.02/
  €0.03 pair through `ingest_statement`).
- **Tenancy (§4.1-4.5)** — same two adversarial shapes every transport
  slice proves (cross-tenant opaque 404 via `NotFoundError`,
  overlapping-data isolation), proven again for TFC's statement shape.
- **§10 (no invented functionality)** — tier-grant verification,
  cadence enforcement and entity detection are refused in "Out of
  scope" with their owning board ids, not silently attempted.
- **ADR-P3 (transport isolation)** — the new parser imports only
  `fuel_card_parser` types; `test_boundaries.py` stays green.
