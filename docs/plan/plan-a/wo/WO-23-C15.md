### Objective and business value

`app/services/currencies.py` (the per-tenant currency catalogue behind `/currencies`, feeding every invoice/issuing-currency picker) and `app/services/fx.py` (the FX conversion module's own currency-identity list, behind `/fx/currencies`) each hard-code their own `(code, name, symbol, decimal_places / ecb)` tuples. They already disagree on currency names (casing) and coverage (`USD`/`JPY`/`CAD`/`AUD` are seedable tenant currencies with no identity entry in `fx.py`'s registry at all), and the tenant catalogue exposes no `indicative` flag — so a finance user picking a currency on an invoice has no signal that its EUR conversion is an ECB-indicative estimate rather than an official reference rate, even though that exact signal already exists one API call away on `/fx/currencies`.

Business value: this is a smaller, drier version of the FX-convention bug WO-8 already fixed once — two lists of the same real-world fact will diverge, and a currency name/symbol shown on an invoice PDF or export that doesn't match what the FX/ECB-comparison screen calls the same code reads as sloppy data to an accountant, which is exactly the audience whose trust the "audit-ready financial record" promise depends on. Fixing it now (S effort) also removes the last blocker ADR-0026 names before it can be marked fully implemented.

### Scope

**In scope:**
- `app/services/fx.py` becomes the ONE currency-identity registry: extend the existing `Currency` dataclass with `symbol: str | None = None` and `decimal_places: int = 2`; backfill those two fields on the `EUROPEAN_CURRENCIES` entries that the tenant seed already surfaces (`EUR`, `GBP`, `CHF`, `SEK`, `NOK`, `DKK`, `PLN`); normalise every `EUROPEAN_CURRENCIES` display name to Title Case (removes the `"Pound sterling"` vs `"Pound Sterling"` drift — no test asserts the old casing, confirmed by grep); add a new `GLOBAL_MAJORS: tuple[Currency, ...]` for the four global majors already priced in `FALLBACK_RATES` but absent from any `Currency` entry (`USD`, `JPY`, `CAD`, `AUD`), matching `currencies.py`'s existing `USD`/`JPY` metadata exactly (`USD` → `"US Dollar"`/`"$"`/2, `JPY` → `"Japanese Yen"`/`"¥"`/0) so the tenant seed's current display is preserved byte-for-byte; add `ALL_CURRENCIES = EUROPEAN_CURRENCIES + GLOBAL_MAJORS` and `CURRENCY_BY_CODE: dict[str, Currency]`; add `indicative_for(code) -> bool | None` (`True` = known, non-ECB-published; `False` = known, ECB-published; `None` = the code is outside the shared registry entirely — identity/rate provenance genuinely unknown, distinct from a known-indicative rate).
- `app/services/currencies.py`: delete the hand-maintained `_STANDARD` tuple; replace with `_STANDARD_CODES` (the same 9 codes, unchanged) and derive `name`/`symbol`/`decimal_places` for the seed from `fx.CURRENCY_BY_CODE` at seed time — one registry, one place the metadata is typed in.
- `app/schemas/currency.py`: add `indicative: bool | None` to `CurrencyOut`.
- `app/api/routes/currencies.py`: populate `indicative` on all three response paths (`list`, `create`, `set_currency_active`) via `fx.indicative_for(code)`, computed at the response boundary (the `Currency` ORM model gains no column — no migration; `models` must not import `services`, so this cannot live on the model).
- New `backend/tests/test_currency_registry.py`: parity, drift self-test, indicative provenance (incl. the `/currencies` vs `/fx/currencies` cross-check), and the "no third registry" regression guard.
- `docs/architecture/adr/0026-one-validation-engine-one-fx-convention.md`: mark C1.5 implemented; C1.7 stays open.

**Out of scope (anti-scope-creep):**
- **C1.7** (multi-currency reporting across analytics/benchmark/budget) — untouched; a later order.
- **C1.9** (dead AP workflow states) — untouched.
- Validating a tenant-created currency's `code` against the shared registry at write time (`POST /currencies` still accepts any 3-letter code, exactly as today) — no acceptance criterion requires it, and rejecting a legitimate exotic currency a tenant actually transacts in would be a product regression, not a fix. An unknown code still converts to `total_eur = NULL` (§4.15, unchanged) and now additionally reports `indicative: null` rather than silently omitting the signal.
- The `/fx/currencies` (europe-scoped) endpoint's own `indicative` computation (`fx.supported_currencies`, per-date `approximate`-or-`not ecb`) — left exactly as is; it answers a different question (is THIS resolved rate, on THIS date, approximate) than the new tenant-catalogue `indicative_for` (is this CODE's identity known to be non-ECB at all). Both are correct; they are not merged.
- Any DB migration — the `Currency` model is untouched.
- Frontend changes — `CurrencyOut` gains an additive optional field; no SPA change required for this order (a picker could later show the flag; not started here).

### Implementation guidance

1. Characterisation first: run `tests/test_currencies.py tests/test_fx.py tests/test_fx_europe.py` and confirm green before touching anything (behaviour-preserving for every existing surface — none of these three files should need an edit).
2. `fx.py`: add the two dataclass fields with defaults so every existing positional `Currency(code, name, ecb)` call keeps working unchanged; only the codes needing non-default metadata (the 9 in `currencies._STANDARD_CODES`) get explicit `symbol=`/`decimal_places=` keyword args. Title-Case the display names in the same edit (grep first to confirm no test string-matches the old casing — confirmed above).
3. `GLOBAL_MAJORS` codes must carry `ecb=True` (ECB's daily feed does publish USD/JPY/CAD/AUD — they're just outside the "European currency" scope `EUROPEAN_CURRENCIES`/`/fx/currencies` intentionally keeps) — do NOT add them to `EUROPEAN_CURRENCIES` itself, only to `ALL_CURRENCIES`, so `test_currencies_endpoint_lists_all_european`'s `region: "europe"` scope is unaffected.
4. `currencies.py::seed_standard`: replace the `for code, name, symbol, dp in _STANDARD:` loop with `for code in _STANDARD_CODES: meta = fx.CURRENCY_BY_CODE[code]; ... name=meta.name, symbol=meta.symbol, decimal_places=meta.decimal_places`. This is a plain `services`→`services` import — permitted by `test_boundaries.py` (only the web layer is forbidden from services, not sibling services).
5. `routes/currencies.py`: add a small `_out(c: Currency) -> CurrencyOut` helper building the response explicitly (id/code/name/symbol/decimal_places/active/version + `indicative=fx.indicative_for(c.code)`); use it in `list_currencies`, `create_currency`, `set_currency_active`. Explicit construction is deliberate — Pydantic's `from_attributes` auto-conversion would otherwise silently default `indicative` to `None` for every row regardless of the code, which is wrong for a known code.
6. Money/rounding: no money math in this order — `decimal_places` is display metadata only (per `models/currency.py`'s own docstring; storage stays `Numeric(14,2)` / `Money` unaffected). No new float path.
7. Targeted suites while implementing: `test_currency_registry.py test_currencies.py test_fx.py test_fx_europe.py test_boundaries.py`. One full suite at the end, backgrounded (see process rules — ~19–20 min; poll the log yourself).

### Testing requirements

`backend/tests/test_currency_registry.py`:
- `test_seed_standard_matches_fx_registry` — for every code in `currencies._STANDARD_CODES`, assert `fx.CURRENCY_BY_CODE[code]` exists and, after `seed_standard`, the persisted `Currency` row's `name`/`symbol`/`decimal_places` equal the registry entry's fields exactly (proves one source, not a copy).
- `test_no_duplicate_codes_in_registry` — `len(fx.ALL_CURRENCIES) == len({c.code for c in fx.ALL_CURRENCIES})` (the drift self-test: temporarily appending a synthetic duplicate `Currency` to a local copy of the tuple and re-running the same assertion must FAIL, proving the check can actually detect a violation — per template rule 6).
- `test_indicative_none_for_unknown_code` — `fx.indicative_for("XYZ") is None`.
- `test_indicative_true_for_non_ecb_false_for_ecb` — `fx.indicative_for("PLN") is False`, `fx.indicative_for("RSD") is True` (mirrors `test_fx_europe.py::test_non_ecb_currencies_flagged_indicative`'s pairing, applied to the new helper).
- `test_tenant_currency_endpoint_surfaces_indicative` — HTTP: seed a tenant, `POST /currencies {code: "RSD", name: "Serbian Dinar"}`, `GET /currencies` → the RSD row's `indicative` is `True`; the seeded `PLN`-family (`EUR`) row's `indicative` is `False`; a `POST /currencies {code: "XYZ", ...}` row's `indicative` is `None`.
- `test_indicative_agrees_across_currency_and_fx_endpoints` — for `PLN` (in both registries), `GET /currencies` (after creating `PLN` on the tenant) and `GET /fx/currencies` report the same `indicative` value for the same code on the same day (the C1.5 acceptance cross-check: one fact, read two ways, agrees).
- `test_no_third_registry` — `"_STANDARD"` (the old duplicate tuple name) and the string `"Pound Sterling"` no longer appear in `app/services/currencies.py`'s source (grep-equivalent assertion via `Path(...).read_text()`), proving the metadata is not hand-copied a second time.
