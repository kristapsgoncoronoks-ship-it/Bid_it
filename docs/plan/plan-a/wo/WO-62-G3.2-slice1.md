# WO-62 — G3.2 slice 1: the fuel-card parser registry + the Eurowag parser (board G3.2, R20)

**WORK ORDER 62 — G3.2 slice 1: `app.services.transport.fuel_card_parser`
(the deterministic-first parser registry) + `EurowagParser` (the first of
seven networks) + `statement_ingest.ingest_statement` (the real caller of
`fuel_ingest.ingest_transaction` and `supplier_entity.learn_registration`,
closing R20). Effort L (6-12d). Priority P1. Milestone M3. Depends on: G3.1
(WO-61, `supplier_vat_registrations` — satisfied), G1.2 (WO-50,
`fuel_transactions` — satisfied).**

### Objective and business value

Verified at HEAD=`8467993` (this order's baseline, 1412 passed / 10
skipped, confirmed live below): there is no `app/services/transport/
fuel_card_parser.py`, no `app/services/transport/parsers/` package, and no
caller anywhere in the tree for either `fuel_ingest.ingest_transaction`
(WO-50) or `supplier_entity.learn_registration` (WO-61) — both shipped
"correct at the function level, zero real consumers wired in" (WO-61's own
words, mirroring `is_synthetic()`'s WO-49 debut). `TODO.md`'s WO-61 entry
names `G3.2` explicitly as "the natural next slice — the actual per-supplier
PDF/text parsers that would call `learn_registration` for real", and
`docs/architecture/adr/0023-*.md`'s WO-61 status note repeats it verbatim.

`ARCH_plan.md` tags G3.2 **XL** (13-25d) and describes it as a **seven-
network build** — Q8/Port One, BP/Aral, TFC by Moya, E100, Moeve, DKV,
Eurowag — each with a distinct, real, learned format quirk (`BA_fleet_
fuel.md` §5.1's own table). Attempting all seven in one order would repeat
the exact mistake WO-56/57/58 deliberately avoided for G2.6 (also flagged
XL) — that epic shipped as three separate, independently-shippable slices
(period-end + minimum + deadline; annual mop-up + duplicate-block;
document-presence + waivers) rather than one unreviewable order. This order
is **slice 1**: it builds the SHARED infrastructure every future network
parser plugs into (the registry/interface pattern, mirroring the existing
AP-domain `extraction_provider.py` seam) plus **ONE fully-specified
network** as the proof — Eurowag, because it is R20's own worked example
(`BA_fleet_fuel.md` §3.B1: the per-country footer, the BE-BVBA-not-CZ-
factoring-entity anti-example) and the best-specified network in the
harvested text for the ONE thing this order must prove: that a real parser
can call `learn_registration` and land the right entity on the right
country. The remaining six networks are named explicitly as future slices
below — never silently deferred.

Who pays more without this: WO-50 and WO-61 both shipped real, tested,
audited write paths with **zero way to reach them from an actual fuel-card
statement** — the whole point of `fuel_transactions` (the future claim
engine's raw material) and `supplier_vat_registrations` (R20's entity-
correctness requirement, the difference between a claim that survives audit
and one a refund authority can reject on sight for naming the wrong
seller) stays theoretical until a parser exists that produces their real
inputs. Every future G2.4/claim-construction consumer of `fuel_transactions`
is also blocked on there being ANY data in that table outside a test
fixture.

### Scope

**In scope**
- `app/services/transport/fuel_card_parser.py` (**new**) — the registry:
  `ParsedFuelLine`/`DetectedEntity`/`ParsedStatement` dataclasses,
  `FuelCardParser` ABC (`handles()`/`parse()`), `register()`/`parsers()`/
  `select()`/`run()`. Deterministic-first: registration order = try order,
  first `handles()` match wins, `select()` raises `ValueError` (never
  guesses) when no parser recognizes a file — see the module docstring for
  why this mirrors `app.services.extraction_provider`'s PATTERN without
  reusing its AP-invoice-shaped OUTPUT TYPE.
- `app/services/transport/parsers/` (**new package**) — one module per
  network. This order ships `eurowag.py` (`EurowagParser`): reads a
  Eurowag statement's transaction CSV block into `ParsedFuelLine`s and
  anchors the per-country seller footer (`"Pārdevējs / Verkoper:"` +
  the harvested legal-form token set) into `DetectedEntity`s — see
  Implementation guidance §1-2 for exactly what is verbatim from
  `BA_fleet_fuel.md` §3.B1 vs a documented interpretation of the
  (unspecified) transaction column layout.
- `app/services/transport/statement_ingest.py` (**new**) —
  `ingest_statement()`: gates on the `transport` entitlement first, runs
  the parser registry, resolves every line's EUR figures via
  `app.services.fx.to_eur` BEFORE writing anything (the "two-phase write" —
  see Implementation guidance §3), then calls `fuel_ingest.
  ingest_transaction` per line and `supplier_entity.learn_registration` per
  detected entity. Network is READ FROM THE PARSED STATEMENT
  (`parsed.network`), never a caller-supplied string — a mislabeled upload
  cannot be miscategorized.
- `tests/factories/transport.py` — `synthetic_eurowag_statement()`, a
  synthetic (never client-derived) statement-text builder, overridable rows/
  footer for negative-case fixtures.
- Tests: the registry (fail-closed selection), the Eurowag parser (line
  extraction, the malformed-row-aborts-the-whole-statement rule, the R20
  anti-example), and the DB-touching orchestration (idempotency, R22
  end-to-end through a REAL caller for the first time, the FX two-phase
  guarantee, cross-tenant isolation, module-off inertness).
- `docs/transport/rules.md` (R20 row — now genuinely closed, not deferred),
  `docs/architecture/adr/0023-*.md` (implementation-status note), `TODO.md`.

**Out of scope** (explicitly, future slices — `G3.2` continues)

  2. **Q8/Port One** — monthly-PER-COUNTRY cadence, list-price invoicing

     this order's Eurowag parser never populates `net_eur_eff` explicitly,

  3. **DKV** — SEK/EUR, semi-monthly, a flat 1.30 SEK/L diesel discount

  4. **TFC by Moya** — monthly, a HUB-ONLY discount (-0.205/L at TFC hubs,

  5. **Moeve (ex-Cepsa)** — monthly, ALL amounts VAT-inclusive, per-line

  6. **BP/Aral (B2Mobility)** — monthly, PLN, Poland split-payment (MPP)

- **`net_eur_eff` off-invoice rebate modeling** — Eurowag carries none per

### Implementation guidance

1. **Read `BA_fleet_fuel.md` §3.B1 (lines 376-425) before writing the
   entity regex.** The footer label `"Pārdevējs / Verkoper:"` and the
   legal-form token set `(BVBA|GmbH|UAB|SIA|s.r.o.|d.o.o.|a.s.|S.A.|AB|SE
   |BV)` are VERBATIM from the source — copy them exactly, the way
   `product_group.py`'s diesel token list is copied verbatim. The anti-
   example (the Czech "W.A.G. Issuing Services, a.s." factoring entity
   must NEVER be picked up) is the load-bearing test case — write it as a
   fixture where BOTH a genuine seller line AND an unrelated factoring
   disclosure sentence appear in the same document, and assert only the
   seller line's entity is detected.
2. **What is NOT given, and must be flagged as a documented
   interpretation, not invented "spec":** `BA_fleet_fuel.md` §5.1's own
   network table lists Eurowag as `(parser only)` — unlike every other
   network, it carries no cadence/currency/quirk cell, meaning the source
   text never specifies an exact transaction column layout for it. Choose
   a small, obviously-representative CSV shape (see the shipped
   `eurowag.py` module docstring for the exact columns) and say so loudly
   in the parser's own docstring — mirroring WO-50's `line_seq`
   disclosure and WO-52's heuristic-interpretation disclosure. Do NOT
   present an invented column layout as if it were harvested.
3. **The FX two-phase write is the load-bearing correctness property.**
   `ingest_statement` must resolve EVERY line's EUR figure (via
   `app.services.fx.to_eur`) in a first pass, entirely in memory, BEFORE
   calling `fuel_ingest.ingest_transaction` for any of them — a statement
   where line N has no cached ECB rate must write ZERO rows, not N-1. This
   mirrors `app.services.expenses.build_items`'s existing all-or-nothing
   FX behaviour (no try/except around `apply_item_fx` in that loop) — the
   established codebase precedent for "a batch of money amounts is
   all-or-nothing on FX", chosen deliberately over a "skip the
   unconvertible line and continue" design, which would silently
   under-report a period's fuel spend with no structural signal anything
   was dropped.
4. **A malformed row aborts the WHOLE statement at parse time**, before FX
   resolution even starts — never a per-row skip. This is cruder than the
   real tie-out regime G3.3 will add (exact line-count vs the invoice PDF,
   a warn/error lattice) but is the correct STOP-GAP: silently dropping a
   bad row would be indistinguishable from silently losing money.
5. **The network is read from `ParsedStatement.network`, never accepted as
   a caller parameter on `ingest_statement`.** This is a deliberate
   design choice beyond what any R-number strictly requires: it makes "the
   file was mislabeled/misfiled as network X but is actually network Y"
   structurally impossible, rather than merely tested against.
6. **`select()`/`run()` raise `ValueError`, matching
   `app.services.extraction_provider.select()`'s own convention**;
   `ingest_statement` is the seam that upgrades that into a
   `ValidationError(code="unrecognized_fuel_card_statement")` at the
   service boundary — services raise `AppError`, never let a bare
   `ValueError` escape to a future route (master-context §4.1).
7. **Every monetary figure is a `Decimal`, never a `float`**, from the CSV
   `str` straight into `Decimal(...)` — `_decimal()`'s helper in
   `eurowag.py` is the ONE place that conversion happens, raising
   `ValueError` on `InvalidOperation`, never silently defaulting to `0`
   (contrast with the AP-domain `parser._to_decimal`'s own default-on-
   failure behaviour — deliberately NOT reused here, since a defaulted
   fuel-line amount is a money-correctness hazard the AP path's softer
   "best-effort draft a human reviews" contract does not carry the same
   way a claim-bound transaction figure does).

### Invariants this order must preserve

- **§4.9 (`Decimal`, never `float`)** — every money field flows CSV-string
  -> `Decimal` directly; `q2` rounding still happens exactly once, inside
  `fuel_ingest.ingest_transaction` (WO-50's existing convention, unchanged).
- **§4.14/§4.15 (no aggregate/guessed cross-currency figures; the ONE FX
  convention)** — `_resolve_line` never stores a NULL or guessed
  `net_eur`/`vat_eur`; a missing ECB rate refuses the WHOLE statement.
- **§4.16 (every mutating operation is audited)** — no new audit action;
  `ingest_transaction`'s existing per-insert audit and
  `learn_registration`'s existing per-seed audit both still fire exactly
  once per real write, composed unchanged by the new orchestrator.
- **ADR-P3 rule 2 / `test_transport_services_do_not_import_other_domain_
  models`** — `fuel_card_parser.py`/`parsers/eurowag.py`/
  `statement_ingest.py` import ONLY `app.models.transport.*` and
  `app.services.*` (never `app.models.fx`, `app.models.invoice`, etc.)
  — proven by the pre-existing boundary test running unmodified over the
  new files (`rglob` already covers the new `parsers/` subpackage).
- **R21 (marker-only matching, no fuzzy auto-pairing)** — `EurowagParser`
  anchors ONLY to the literal seller-label line; `statement_ingest` passes
  the detected `(country, vat_number, entity_name)` straight to
  `learn_registration` with no normalization/similarity step of its own.
- **R22 (learning never clobbers a curated value)** — proven END TO END
  for the first time through a REAL caller
  (`test_g3_2_ingest_statement_never_overwrites_a_curated_registration`),
  not just at the `supplier_entity` function level (WO-61's own scope).

### Testing requirements

`backend/tests/transport/test_g3_2_fuel_card_parser.py` (pure, no DB):
- registry: `select()`/`run()` raise `ValueError` when no parser
  recognizes a file (`test_g3_2_select_raises_when_no_parser_recognizes_
  the_file`); a partial/incidental marker mention doesn't cause a false
  match (`test_g3_2_select_does_not_match_on_a_partial_marker`);
  `register(..., first=True)` gives priority.
- `EurowagParser.handles()`: recognizes a well-formed statement; refuses a
  file missing the marker; refuses undecodable bytes.
- `EurowagParser.parse()`: every field of a line extracts correctly;
  `line_seq` is 1-based and stable across an identical re-parse; a missing
  required column, an unparseable decimal, an invalid country code, and a
  statement with zero data rows each raise `ValueError` with a message
  naming the problem.
- Entity anchoring: a genuine BE seller line is detected while an
  UNRELATED Czech factoring-entity disclosure sentence elsewhere in the
  document is NOT (`test_g3_2_parse_reads_the_be_bvba_seller_not_the_
  czech_factoring_entity` — R20's own worked example, verbatim); multiple
  country footers in one statement all detect; a seller line with no
  recognised legal form, or no VAT number, or an unresolvable VAT prefix
  each warn and detect nothing (never guess); the Greek `EL`->`GR`
  exception is proven; a statement with no footer at all still ingests its
  transaction lines (entity absence doesn't block money capture).

`backend/tests/transport/test_g3_2_statement_ingest.py` (DB):
- Happy path: `ingest_statement` creates the `FuelTransaction` row(s) AND
  a `SupplierVatRegistration` (`source="capture"`) in one call.
- Idempotency: re-ingesting the IDENTICAL file twice produces exactly one
  transaction row and one registration row (never a duplicate).
- R22 end-to-end: an admin-curated registration set BEFORE ingestion is
  NEVER overwritten by the statement's own captured entity.
- Module-off: `PermissionError` raised BEFORE parsing; zero rows written.
- Cross-tenant: an entity id real in org B, referenced from org A, is a
  `NotFoundError` (opaque, never a leak) — §8's adversarial case.
- Unrecognized statement: `ValidationError(code="unrecognized_fuel_card_
  statement")`; zero rows written.
- Invalid period: `ValidationError(code="invalid_period")`, refused BEFORE
  the file is even parsed.
- The two-phase FX guarantee, both directions: a non-EUR line converts
  correctly via a seeded ECB rate (`fx_source="ecb"`, the exact rate/date
  recorded); a statement with one clean EUR line AND one line in an
  utterly uncached currency (ZAR — deliberately outside this repo's
  bundled ECB/fallback set) writes **NEITHER** line, proving "nothing
  partially applied", not merely "the bad line is skipped".
- Cross-tenant isolation with IDENTICAL statement text ingested into two
  different orgs: zero shared rows, distinct ids (§8's overlap
  discipline).

### Rollback strategy

Pure code addition, no migration. A revert removes `fuel_card_parser.py`,
the `parsers/` package, and `statement_ingest.py` — nothing else in the
tree imports them yet (no route, no worker kind), so a revert is a clean
subtraction with zero blast radius. `fuel_ingest.ingest_transaction` and
`supplier_entity.learn_registration` return to their pre-existing "no real
caller" state, exactly as they were after WO-50/WO-61. No kill switch
needed: the `transport` module stays default-OFF and absent from every
plan's module set, so none of this is reachable by any tenant regardless
of code presence.
