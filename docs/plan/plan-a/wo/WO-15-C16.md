## Verified premise (evidence at `0b0d259`)

ADR-0026 records the defect and the decision ("accepted, not yet implemented — C1.6 … `core/dimensions` is the intended home"). Verified:

1. **Two dimension registries exist.** `backend/app/core/dimensions.py` declares the five cost-allocation dimensions (`cost_center`, `department`, `project`, `vehicle`, `property_ref` — `DIMENSIONS`, lines 16–22), consumed by the fixed report `analytics.by_dimension` and the `/analytics/dimensions` catalog. `backend/app/services/explore.py:73-86` hardcodes a **separate** 9-entry `DIMENSIONS` dict (vendor, country, category, status, validation, currency, month, quarter, year) that does **not** include the five — so a cost dimension is not groupable in Explore, and a sixth dimension added to `core/dimensions` would silently not appear there (the drift ADR-0026 §Risks warns about).
2. **The dimensions live on `Invoice`** (`app/models/invoice.py:177-181`, indexed per-org at 99–101 for the id-links; the free-text tags are the dimension values). Explore's fact grain is the line item; grouping **line amounts by an invoice-level attribute never double-counts** (each line belongs to exactly one invoice), so the extension is additivity-safe by Explore's own docstring rule.
3. **The frontend is catalog-driven** — `frontend/src/pages/Explore.tsx` builds its pickers from `GET /analytics/fields` (`fields.data?.dimensions`); the five new dimensions surface with **zero SPA changes**.
4. **The unassigned convention differs**: `analytics.by_dimension` buckets untagged spend as `"(unassigned)"` (`_UNASSIGNED`, `analytics.py:30`); Explore renders SQL NULL as `"—"`. For the two paths to return the same cut, the constant must live in the registry and both must use it.

### Objective and business value

Explore's dimension list and the fixed by-dimension report read two unrelated registries (`explore.DIMENSIONS` vs `core.dimensions.DIMENSIONS`), so the five cost-allocation dimensions — the ones WO-14 just made *administrable* (masters, pickers-to-come) — cannot be pivoted, filtered by measure, broken down by month, or CSV-exported in the self-service Explore surface at all; they reach exactly one fixed gross-total report. ADR-0026 already ruled this duplication a correctness defect of the same class as the two validators and two FX conventions it fixed ("two registries will diverge"; risk note: "new code touching currencies/dimensions must not add a third registry").

Who stops losing money: a transport or property-management finance lead tags spend by vehicle/property precisely to answer questions like "diesel spend per truck per month" — a cut only Explore can express (two dimensions, any measure). Today the product collects the tag and cannot answer the question, which reads as "unfinished" in a trial (ARCH risk C-6). And I1.1 — the P0 home dashboard, the next order — is specified to read "the canonical registry"; this order is what makes that registry exist as a single source.

### Scope

**In scope:**

*Backend:*
- `app/core/dimensions.py`: add the shared `UNASSIGNED = "(unassigned)"` constant (the registry owns the convention both consumers render).
- `app/services/explore.py`: derive the five cost-allocation `Dimension` entries **from `core.dimensions.DIMENSIONS`** (key + label taken from the registry; expr = `func.coalesce(Invoice.<key>, UNASSIGNED)`), appended to the pivot's dimension dict. A dimension added to the core registry then appears in Explore, the fixed report, `/analytics/dimensions` and `/analytics/fields` with no further change — one registry, all consumers.
- `app/services/analytics.py`: replace the private `_UNASSIGNED` with the registry's `UNASSIGNED` (behaviour-identical; single-sources the label).
- `app/api/routes/analytics.py`: the `by-dimension` query-param description derives from `DIMENSION_KEYS` instead of a hand-maintained string list (doc-string drift removal; no wire change).

*Tests (new `backend/tests/test_dimension_registry.py`):* see Testing requirements — including the C1.6 acceptance cross-check (Explore and the fixed report return identical numbers for the same cut) and a parity self-test that proves the drift detector detects.

**Out of scope (anti-scope-creep):**
- The composed home dashboard — **I1.1** (this order unblocks it; does not start it).
- One **currency** registry — **C1.5**; multi-currency analytics (`analytics.summary()` hard-coding `"EUR"`) — **C1.7**. This order deliberately does not touch `summary()`.
- Explore **filters** on cost dimensions (e.g. `?cost_center=`) and cost-dimension pickers on invoice/expense forms — the Slice-2 follow-up recorded by WO-14; not needed for the C1.6 acceptance.
- Expense-line analytics: Explore's fact grain stays the AP line item (expenses carry the same dimension columns but have their own reporting surface; extending Explore's grain is new capability, not registry unification).
- Any change to Explore's **measure** math (its `tax`/`gross` sum per-line unrounded expressions predate this order; per-line rounding parity with `Invoice.tax_amount` is noted as a follow-up, not silently changed here).
- Frontend changes (catalog-driven; none needed) and any migration (none — the columns exist and are indexed).

### Implementation guidance

1. Characterisation first: run `tests/test_explore.py tests/test_dimensions.py tests/test_analytics.py` and confirm green before touching anything (behaviour-preserving for every existing surface).
2. `core/dimensions.py`: `UNASSIGNED: str = "(unassigned)"` with a one-line why ("both the fixed report and Explore bucket untagged spend under this label so the two paths return the same cut").
3. `explore.py`: build the entries with a helper taking `key`/`label` as parameters (never a bare closure over a loop variable — late binding would point every lambda at the last key). SQL-side `coalesce` (not Python-side) so `GROUP BY` merges NULLs into the bucket. Non-temporal → default value-desc ordering applies unchanged.
4. `analytics.py`: alias the import (`from app.core.dimensions import UNASSIGNED as _UNASSIGNED` is acceptable) or rename uses; no behaviour change — `test_by_dimension_breakdown` must pass unmodified.
5. Money basis for the cross-check test: the fixed report sums `Invoice.total` (gross, per-line-quantized tax); Explore's `gross` measure sums `amount × (1 + rate/100)` unrounded. Seed fixtures whose per-line tax is **exact at 2dp** (e.g. `100.00 @ 20%`, `40.00 @ 21%`, `25.00 @ 0%`) so both paths are exactly equal and the assertion is string-exact, not tolerance-based. State this in the test docstring; the measure-rounding nuance is the recorded follow-up, not this order's scope.
6. Targeted suites (`test_dimension_registry.py test_explore.py test_dimensions.py test_analytics.py test_authz_routes.py`) while implementing; ONE full suite at the end in the background.
