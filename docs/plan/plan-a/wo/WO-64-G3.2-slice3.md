### Objective and business value

Verified at HEAD=`410c801` (this order's baseline, confirmed live below):
`app/services/transport/parsers/` contains exactly two modules
(`eurowag.py`, `e100.py`); `fuel_card_parser._default_parsers()` registers
exactly `[EurowagParser(), E100Parser()]`. `TODO.md`'s WO-63 entry and
`docs/architecture/adr/0023-*.md`'s WO-63 implementation-status note both
name the same next-slice priority list, Q8/Port One first among the five
remaining networks. `BA_fleet_fuel.md` §5.1's own network table gives Q8
one real, learned quirk beyond a generic list-price invoice: *"Invoiced at
LIST price; separate Port One rebate invoice per country -> the
`net_eur_eff` layer. Per-line country + currency."* This order builds the
half of that sentence which is a genuine SINGLE-FILE PARSER concern — Q8's
own list-price money model (independently-given `net_local`/`vat_local`/
`gross_local`, the same shape Eurowag already proved, not E100's reverse-
calculation) and, for the first time in this codebase, a statement that
legitimately spans MORE THAN ONE COUNTRY AND CURRENCY in a single upload.
Neither `eurowag.py` nor `e100.py`'s own fixtures/tests ever exercised
more than one country per file, even though the `ParsedFuelLine`/
`fuel_transactions` schema has always carried country/currency PER LINE
(WO-50) — this is the first order that actually proves that capability
end to end.

Who pays more without this: `fuel_transactions` stays reachable from only
two of seven real networks; Q8/Kuwait Petroleum is named as a live,
paying, monthly-per-country-cadence network in `BA_fleet_fuel.md` §5.1 for
the «Client-EE» entity specifically, and every one of that entity's Q8
statements has no path into the claim engine at all until this order
lands. Q8 is also the first proof that this registry's "one file, one
network, per-line country" design actually holds up against a network
whose OWN cadence forces multi-country activity through a single portal
export, rather than coincidentally always being single-country the way
Eurowag/E100's fixtures happened to be so far — de-risking the pattern
before the harder remaining networks (DKV's SEK/EUR dual-currency
service-fee lines, BP/Aral's mandatory Polish split-payment) build on it.

### Implementation guidance

1. **The list-price money model.** Q8's own invoice supplies `net_local`/
   `vat_local`/`gross_local` independently (list-price invoicing — not
   VAT-inclusive gross the way E100's is), so `Q8Parser` reuses
   `eurowag.py`'s exact CSV column shape (`txn_date,txn_time,vehicle_ref,
   station,country,product,qty,currency,net_local,vat_local,gross_local,
   invoice_ref`) behind a distinct `"Q8 STATEMENT"` marker line, with no
   reverse-calculation step. This is a DOCUMENTED INTERPRETATION exactly
   like `eurowag.py`'s own column-shape choice (no worked Q8 invoice
   layout is given in the harvested spec either) — say so in the module
   docstring, mirroring both prior parsers' own "verbatim vs documented
   interpretation" sections.
2. **The multi-country/currency proof.** `synthetic_q8_statement()`'s
   DEFAULT fixture (no `rows` override) must itself carry two rows in two
   different (country, currency) pairs (e.g. EE/EUR and PL/PLN) — every
   test in `test_g3_2_q8_fuel_card_parser.py`/`test_g3_2_q8_statement_
   ingest.py` that calls the factory with no override therefore already
   exercises the multi-country path, and at least one test asserts it
   EXPLICITLY (`{line.country for line in parsed.lines} == {"EE", "PL"}`).
   At the ingestion level, the non-EUR line converts through the SAME
   `statement_ingest._resolve_line`/`app.services.fx.to_eur` path every
   prior network already uses — no new FX code, a cached ECB rate for the
   PLN test date must be loaded via `fx.load_rates` before the call
   (mirrors `test_g3_2_e100_statement_ingest.py`'s own PLN test).
3. **No entity detection, ever, for Q8.** `Q8Parser.parse()` must not
   contain any regex/marker scan over the statement text at all —
   `entities` is unconditionally `[]`. Surface exactly ONE warning per
   parse (not per line) whose wording makes explicit that detection was
   never attempted — distinct from `eurowag.py`/`e100.py`'s "no marker
   found in THIS document" wording, so a human reading `warnings` cannot
   mistake "we looked and found nothing" for "we never looked". Add an
   adversarial test that plants a plausible "Kuwait Petroleum ... VAT: ..."
   line in the raw file text and asserts `entities` stays `[]` — proving
   the absence is structural, not accidental (no scan exists to
   accidentally match it), matching master-context §8's "assert the
   absence, not only the presence" rule.
4. **`net_eur_eff` — deliberately untouched.** `statement_ingest.
   ingest_statement`'s call into `fuel_ingest.ingest_transaction` passes no
   `net_eur_eff` argument for ANY network today (grep confirms this); do
   not add one for Q8 either. Add an explicit ingestion-level test
   asserting `txn.net_eur_eff == txn.net_eur` for every ingested Q8 line —
   the "we did not silently start computing this" backstop, matching how
   WO-63 proved the SAME non-behaviour for E100's reverse-calculated
   figures.
5. **Registration.** `fuel_card_parser._default_parsers()` gains one line,
   `Q8Parser()`, appended third. Confirm (as a test) that `handles()`
   markers cannot collide across all three parsers — `"EUROWAG
   STATEMENT"`, `"E100 STATEMENT"`, `"Q8 STATEMENT"` are three distinct
   literal first-line strings, so registration ORDER remains provably
   irrelevant to correctness (same reasoning WO-63 already documented,
   restated for three).

### Invariants this order must preserve

- **§4.9 (Decimal, ROUND_HALF_UP, never float)** — `Q8Parser` returns
  UNROUNDED `Decimal`s exactly like `eurowag.py`/`e100.py`; the ONE
  rounding point remains `fuel_ingest.ingest_transaction`'s `q2` calls,
  unchanged.
- **§4.14 (no aggregate sums across currencies without a recorded
  conversion)** — proven directly by the multi-country/currency ingestion
  test: the PLN line's `fx_source == "ecb"`/`fx_rate` is recorded, the EUR
  line's is the identity conversion; no code path sums the two raw.
- **§4.15 (one FX convention; `unknown` ⇒ refuse, never guess)** — the
  no-cached-rate adversarial test proves the WHOLE statement (including
  the clean EUR line) writes ZERO rows when a later line's currency has no
  cached ECB rate — the existing two-phase-write guarantee, exercised
  again for a third network.
- **Tenancy (§4.1-4.5)** — the cross-tenant-404 and cross-tenant-isolation-
  with-overlapping-data tests are the SAME two adversarial shapes every
  prior transport-ingestion order has proven; this order proves them again
  for Q8's statement shape specifically (two countries, not one).
- **§10 "no invented functionality"** — the Out-of-scope section's
  Port-One-rebate-merge and entity-detection refusals are the direct
  application of this prohibition; both are documented, not silently
  dropped.
