R7's own text (`docs/audit/remediation-roadmap.md` lines 322-328) and the debate verdict

`backend/tests/test_filesec.py`'s 8 existing tests never set `clamav_enabled=True` and never touch the

### Objective and business value

`filesec.scan_malware()` is the single malware-scan choke point sitting in front of every intake surface
(manual upload, email intake, bank statements, receipts — see the module docstring). Its ClamAV integration
is off by default (`clamav_enabled: bool = Field(default=False)`, `app/core/config.py:134`) and `clamd` is
not even an installed dependency today (commented out at `requirements.txt:46`), so in the shipped default
configuration this branch is unreachable — hence P2, not P0/P1. But the moment an operator turns
`clamav_enabled` on for a real deployment (this product moves vendor bank files and invoice PDFs — a
credible near-term need), a silent regression to fail-open on this exact branch would defeat the AV gate
with zero test signal to catch it. Closing this now costs ~15 lines of monkeypatch-based test and buys a
permanent CI trip-wire on a security control that currently has none.

Who benefits: every future customer whose deployment enables ClamAV — the regression-prevention gap closes
before it can ever be exploited, at effectively zero engineering cost (test-only, no `clamd` daemon or
package required to run in CI).

### Scope

**In scope:**
- Add tests to `backend/tests/test_filesec.py` covering `scan_malware()`'s three CONFIGURED-scanner
  branches (`clamav_enabled=True`), using a fake `clamd` module injected into `sys.modules` (no real
  daemon, no real package needed):
  1. **FOUND** — `cd.instream(...)` returns `{"stream": ("FOUND", "<signature>")}` → `FileRejected` with
     the signature in the message.
  2. **non-OK status** — `cd.instream(...)` returns `{"stream": ("ERROR", None)}` (or any status that is
     neither `FOUND` nor `OK`) → `FileRejected` ("Virus scan returned an error").
  3. **unreachable/exception** — `cd.instream(...)` raises (simulating a daemon that is configured but not
     reachable) → `FileRejected` ("Virus scan is unavailable — file rejected"), i.e. fail-CLOSED.
  4. (Completeness, not separately required by the acceptance bar but cheap to add) a **clean/OK** positive
     case — `cd.instream(...)` returns `{"stream": ("OK", None)}` → no exception, file passes.
- Also cover the ClamdUnixSocket vs ClamdNetworkSocket branch selection (`settings.clamav_unix_socket` set
  vs unset) so both connection paths are exercised at least once.
- A **self-test**: seed a deliberate regression (e.g. monkeypatch `scan_malware` to swallow the FOUND
  result / patch behavior so it does NOT raise) and assert the new tests actually catch it — satisfies the
  "a test that cannot fail proves nothing" rule (WORK_ORDER_TEMPLATE.md §"How to write good test
  requirements" item 6). This is exercised manually during implementation (see Testing requirements) and
  does not need to ship as a permanent test.

**Out of scope:**
- No change to `app/services/filesec.py` application code — the control is already correct (confirmed by
  `agent-debate.md` §7 and independently reproduced in this WO's red-then-green proof).
- No change to `requirements.txt` (clamd stays commented-out/optional) — do not install or declare a new
  runtime dependency.
- R14/R16/R18 — separate, later work orders.
- No live/real ClamAV daemon integration test — out of scope per the debate's own finding that a fake
  `sys.modules["clamd"]` injection is sufficient and appropriate (no daemon in CI).

### Implementation guidance
1. In `test_filesec.py`, add a small helper that builds a fake `clamd` module object with a
   `ClamdUnixSocket`/`ClamdNetworkSocket` class whose `instream()` returns/raises a caller-supplied value,
   and injects it into `sys.modules["clamd"]` for the duration of a test (via `monkeypatch.setitem` on
   `sys.modules`, restored automatically after the test).
2. For each test: `monkeypatch.setattr(filesec.settings, "clamav_enabled", True)`, inject the fake `clamd`
   module, call `filesec.scan_malware(<some clean, non-EICAR content>)`, and assert the expected outcome.
3. Cover both `clamav_unix_socket` set (`ClamdUnixSocket` used) and unset (`ClamdNetworkSocket` used with
   `clamav_host`/`clamav_port`) — assert via a flag/spy on which class was instantiated, not just the
   outcome, so a future refactor that silently drops one connection mode is caught.
4. Use plain, non-EICAR content for the scanner-branch tests (EICAR is already covered by the existing
   `test_rejects_eicar_malware_signature`, and it short-circuits before the `clamd` import — using it here
   would test the wrong code path).
5. RED-then-GREEN proof: before finalizing, temporarily break the fail-closed behavior in `filesec.py`
   locally (e.g. comment out the `except Exception` re-raise, or flip the `status != "OK"` check) and
   confirm the new tests fail; then restore the original code and confirm green. Do not leave this
   temporary breakage committed — it is a manual verification step, reported in the final report, not a
   shipped file change.
6. No `app/services/filesec.py` change is expected. If, contrary to the debate's finding, a real bug turns
   up while writing these tests (e.g. the branches don't actually behave as documented), stop and report it
   — per the master-context §9 "if the plan looks wrong" rule — rather than silently patching around it.
