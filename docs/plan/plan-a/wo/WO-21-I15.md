## Implementation guidance

1. **`report_writers.py` first, as pure functions over the `explore.run()` result dict** (no I/O beyond the in-memory buffer, unit-testable without the DB):
   - `_safe_cell(value: str) -> str`: identical neutralisation rule to `erp_export._safe`/`audit_export._safe` (leading `=`,`+`,`-`,`@`, tab, CR → prefixed with `'`). Apply it to **every** cell value written to the xlsx sheet, including the measure value column (a negative number formats as a leading `-` string and is a live Excel formula trigger exactly like a leading `=`).
   - `to_xlsx(result: dict) -> bytes`: `openpyxl.Workbook()`, one sheet, header row = dimension labels + measure label (same order as `to_csv`), data rows = `_safe_cell()`-wrapped dimension values + measure value string. Return `io.BytesIO` buffer's bytes (`wb.save(buf); return buf.getvalue()`). Bold the header row for readability (a cosmetic touch, not a requirement) — keep it minimal, no charts/formatting complexity.
   - `to_pdf(result: dict) -> bytes`: reportlab `SimpleDocTemplate` + `Table`, reusing the styling constants pattern from `invoice_pdf.py` (`_BRAND`/`_INK`/`_MUTED`/`_LINE` — either import them or redeclare locally; prefer a local minimal palette to avoid coupling a generic report writer to the invoice module). Title = `"{measure.label} by {dim1.label} × {dim2.label}"` (or just the measure label with zero dimensions), a "Generated at <UTC timestamp>" subtitle, then one `Table` with the same header/row content as the xlsx (PDF text is never executed as a formula — no injection concern here, skip `_safe_cell`). Cap displayed rows at a sane bound (reuse the existing `ExploreQuery.limit` cap of 1000 — the caller already bounds `rows`) so a pathological cut does not produce an unbounded PDF.
   - Both must handle the zero-dimension case (`result["dimensions"] == []`, a single-row "grand total" cut) without crashing — the header row is then just `[measure.label]`.
2. **Route** (`analytics.py::get_explore`): widen `format: str = Query(default="json", pattern="^(json|csv|xlsx|pdf)$")`. After the existing `csv` branch, add:
   ```python
   if format == "xlsx":
       return Response(
           content=report_writers.to_xlsx(result),
           media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
           headers={"Content-Disposition": content_disposition("explore.xlsx")},
       )
   if format == "pdf":
       return Response(
           content=report_writers.to_pdf(result),
           media_type="application/pdf",
           headers={"Content-Disposition": content_disposition("explore.pdf")},
       )
   ```
   Import `report_writers` and `content_disposition` at the top of the module (the latter already exists in `app.core.security_headers`, used elsewhere in the codebase — e.g. `export.py`).
3. **Frontend**: two more `<button className="btn-ghost" onClick={() => downloadFile(...)}>` calls beside the existing `Export CSV` button, using the same `params` query string with `&format=xlsx` / `&format=pdf` and filenames `explore.xlsx` / `explore.pdf`.
4. **Tests** — write the empty/zero-row case first (characterisation for the edge the acceptance criteria call out), then the populated case, then the injection case:
   - `test_report_writers.py::test_to_xlsx_roundtrips_header_and_rows` — build a `result` dict by hand, call `to_xlsx`, re-open with `openpyxl.load_workbook(io.BytesIO(...))`, assert header row and data rows match.
   - `test_report_writers.py::test_to_xlsx_neutralises_formula_injection` — a dimension value of `"=cmd|'/c calc'!A1"` (and separately a measure value that renders with a leading `-`, e.g. a negative net figure) must land in the cell as a string starting with `'=`/`'-`, never a raw formula-triggering leading character; assert `cell.data_type` is not treated as a formula by openpyxl on reload (openpyxl reads a leading-quote-prefixed value back as the literal text, including the quote character stripped by Excel's own convention — assert the stored string still starts with the safety prefix character, i.e. the raw first character is never `=`/`+`/`-`/`@`/tab/CR).
   - `test_report_writers.py::test_to_pdf_returns_valid_pdf_bytes` — assert the output starts with `b"%PDF"` and is non-trivial length; optionally parse with `pypdf.PdfReader` (already a dependency) and assert `len(reader.pages) >= 1`.
   - `test_report_writers.py::test_writers_handle_zero_dimensions` — a `result` with `dimensions: []` and one grand-total row does not raise for either writer.
   - `test_explore.py::test_xlsx_and_pdf_export` — extend the existing `auth_client`-driven test file: `GET /api/v1/analytics/explore?measure=net&dim=category&format=xlsx` → 200, `content-type` starts with the openpyxl media type, non-empty body; same for `format=pdf` → `content-type` starts with `application/pdf`.
   - One permission-denied case: a role without `REPORT_READ` (reuse whatever fixture the router's existing tests use for the denied-role case on this router — check `test_explore.py`/`test_ap_aging.py` or similar for the established low-privilege client fixture) gets 403 on `format=xlsx` — this is inherited for free from the router-level dependency, but assert it explicitly for the new formats since it is new *code path*, not just new format string.

## Invariants this order must preserve

- **§4.20 (wire contract, additive change)** — `format=json`/`format=csv` behaviour is byte-identical; `xlsx`/`pdf` are pure additions to an existing enum-validated query param, never a breaking change to an existing client.
- **§4.10-adjacent (no invented figures)** — both writers consume the *already-computed* `explore.run()` result; neither writer performs its own aggregation or touches the DB. A test should assert the xlsx/pdf row values match the JSON/CSV values for the identical query (same `result` dict in, three different serialisations out).
- **Money is quantized** (§4.9) — the writers format the *already-`_fmt`-formatted* string values from `explore.run()`; they must not re-derive or re-round a figure from a float.
- **Formula-injection safety extends to the new medium** (I1.5's own acceptance line) — proven by `test_to_xlsx_neutralises_formula_injection`, not merely asserted.
- **Authorization stays structural (§4.7/A1.1)** — no new permission dependency needed or added; the two new format branches sit inside the same already-gated route.

## Testing requirements

- One granted-role case (`auth_client` fixture, already has `REPORT_READ` via its default seeded role) for both `format=xlsx` and `format=pdf` returning 200 with the correct media type.
- One denied-role case: a client fixture without `REPORT_READ` gets 403 on `format=xlsx` (mirror whatever existing low-privilege fixture the analytics test suite already uses for its permission tests, e.g. `role_client` if present in `conftest.py` — verify the exact fixture name before writing the test rather than inventing one).
- No cross-tenant case is needed beyond what the router already proves (Explore's `run()` is already `org_id`-scoped and covered elsewhere) — this order adds no new query path, only new serialisations of an existing, already-scoped result.
- No concurrency/idempotency case applies — both writers are pure, stateless functions over an in-memory dict.
- Adversarial case from §8 that applies: **malformed/adversarial input at the boundary** — the formula-injection test above (`=`, leading `-`) is this order's instance of that category, applied to the new Excel medium specifically (CSV/erp_export already cover it for CSV).
