**WORK ORDER 74 — G2.12: the Excel claim workbook + the ZIP evidence pack —
the two filing artifacts of a frozen VAT refund claim, built from ONE line
source, both refusing any synthetic line (board G2.12). Effort M 3–5d.
Priority P1. Milestone M3. Depends on: WO-54 (G2.5 frozen lines), WO-55 (G2.8
goods codes), WO-49 (R3 `is_synthetic`), WO-58 (R10 document gate — the
presence guarantee the pack assembles against).**

### Objective and business value

The claim pipeline can now build (WO-52), gate (WO-56/57/58/73), freeze
(WO-54) and lock (WO-51) a VAT refund claim — but it cannot produce the thing
the operator actually FILES. `BA_fleet_fuel.md` §2.2 names the artifacts of
the claim lifecycle: *"the Excel claim workbook (`build_workbook`), the
evidence pack, the fee report, …"* (lines 204–205), and §3.K K6 defines the
second: *"`vat_refund.evidence_pack(entity, refund_country, period)` assembles
the filing bundle. The vault tree is human-navigable and identical across
backends: `Customer (reg no) / Year / Country / Claim period / file`"* (lines
741–744). Neither exists in `backend/app/services/transport/` — `grep -rn
"workbook\|evidence" backend/app/services/transport/` returns nothing. R3's
own ledger row (`docs/transport/rules.md`) still reads *"used by (future)
lock/checklist/readiness/**workbook** gates"* — the workbook builder is the
fourth named consumer of `claim_gates.is_synthetic()` and the one this order
finally wires.

Who stops losing money: the refund agent's deliverable to the tax portal IS
the workbook, and the audit-defence deliverable to a member-state's follow-up
questions IS the evidence bundle (Art. 10/20 Dir. 2008/9/EC — the refunding
state may demand the invoice originals). A workbook whose figures can drift
from the filed claim, or a bundle missing an invoice document, converts a
recoverable claim into a rejected one — and a rejected claim's invoices stay
locked (R5), so the money is *gone*, not delayed. The identical-lines-and-
totals guarantee between the two artifacts is the product promise ("an
audit-ready financial record") made concrete.

### The harvested specification — the standing order's questions, answered with citations

**1. Exact workbook structure (sheets/columns).** The harvested spec
deliberately does NOT preserve Fleet Fuel's sheet/column layout — it names the
artifact (`build_workbook`, §2.2 line 204) and pins only three structural
facts: the line grain is *"one row per (invoice, product code) — never an
`ALL:` aggregate"* (§3.C C1, R2), every line carries an Art. 9 goods code
(R11), and the workbook builder blocks synthetic lines with the same predicate
as the other three gates (§3.C C2, R3 line 1360). The layout below is
therefore a **recorded interpretation, not a harvest**:
- Sheet `Claim` — the claim header: entity legal name / VAT number /
  registration number, refund country, period (`ref_period` + human label),
  engine status + workflow code, submitted date, frozen VAT base (EUR and
  local + currency), line count, generated-at (UTC).
- Sheet `Lines` — one row per frozen `VatRefundClaimLine` (the R2 grain):
  Supplier, Invoice number, Invoice date, Goods code (Art. 9), Product group,
  Net EUR, VAT EUR, Net local, VAT local, Currency; a final TOTAL row whose
  EUR/local sums equal the claim's frozen `vat_eur`/`vat_local` exactly.
  Deterministic ordering `(invoice_ref, product_group)` — the same sort
  `claim_lines.build_claim_lines` writes in.

**2. Evidence pack vs workbook.** Two different artifacts for two different
readers. The **workbook** is the figures document the operator files with the
claim (§2.2 line 204). The **evidence pack** is the *filing bundle* (§3.K K6,
lines 741–744): a ZIP assembling the workbook PLUS every vaulted source
document (the invoice PDFs R10 guaranteed present at submission) under the
human-navigable vault tree `<Customer> <RegNo> / <Year> / <Country> /
<Claim period> / <file>` (§3.M M1, lines 766–769: *"every segment is
sanitized for Windows/SharePoint/FTP safety"*; `period_label()` maps
`2026-Q3 → Q3`, `2026-YEAR → Annual`), plus a `manifest.csv` naming each
file's SHA-256 — the same manifest discipline the spec's backup/integrity
section establishes (§3.K K4). ARCH_plan's acceptance: *"the workbook and the
evidence pack agree line-for-line"* — the same both-artifacts-one-source rule
R41 (line 1413) states for the overcharge packet: *"built from the SAME line
source … Both artifacts for the same (supplier, period) show identical lines
and totals."*

**3. Where the refusal rules sit.**
- **Synthetic-line refusal** — §3.C C2 (lines 433–443): *"A pack containing
  ANY synthetic line CANNOT be filed"*, enforced via THE single
  `claim_gates.is_synthetic()` predicate (R3: *"used by the lock gate, the
  checklist gate, the readiness check AND the workbook builder … so they all
  block the same set of synthetic refs"*). This order reuses WO-49's one
  predicate — never a second implementation — and both artifacts share one
  loader, so the refusal is written once and hit by both.
- **Non-frozen/draft refusal** — the harvested Fleet Fuel derived claim lines
  LIVE forever (§3.C C1) and protected the filed claim only by a physically
  separate legal DB; ADR-P3 translated that into materialize-and-freeze at
  submission (G2.5, `freeze.py`: *"after submission, editing or re-closing the
  underlying period changes nothing about the filed claim"*; spec §4.3: the
  VAT base is *"FROZEN at submission over exactly the locked claim_set"*).
  The faithful translation for the FILING artifacts: they render **frozen
  lines only** (`frozen_at IS NOT NULL`). A draft claim has no frozen lines →
  refused fail-closed (`code="claim_not_frozen"`). A withdrawn claim keeps
  its frozen lines (WO-51's `withdraw_claim` deletes locks, never lines) —
  its artifacts stay reproducible, which is the audit-trail-preserving
  behaviour, and is documented as deliberate.

**4. What triggers generation.** An explicit service call —
`claim_pack.build_workbook(db, org_id, claim_id)` /
`claim_pack.build_evidence_pack(db, org_id, claim_id)`. No route exists yet;
like every transport slice since WO-49, this is service-only with the
`api/routes/transport/*` batch to follow (ARCH_plan M3 tail). Generation is
read-only and repeatable: nothing is persisted, nothing is mutated, no audit
event (the platform's own export precedent — `erp_export.py`,
`report_writers.py` — audits no read-only artifact generation; master-context
§4.16 requires audit on *mutations* only).

### Design decisions (recorded, with rationale)

1. **ONE loader, two renderers.** A private `_load_pack()` performs: module
   gate → org-scoped claim fetch (opaque 404) → frozen-lines-only select →
   synthetic refusal (R3) → totals recomputation + drift check → entity/
   invoice/vendor resolution. `build_workbook` and `build_evidence_pack` are
   thin renderers over its result, and the evidence pack's embedded workbook
   is rendered by the SAME `_render_workbook()` over the SAME loaded pack —
   "identical lines and totals" is structural, not coincidental (the R41/
   `financeable()`-reuses-`recovery_report()` discipline, §3.L).
2. **Totals-drift tamper check (fail-closed).** The renderer recomputes
   `q2(Σ vat_eur)` / `q2(Σ vat_local)` over the frozen lines and REFUSES
   (`code="claim_totals_drift"`) if they differ from the claim's frozen
   `vat_eur`/`vat_local` — the filing artifact must never paper over a
   corrupted frozen set (master-context §4.10 "the server recomputes every
   total", applied to its own stored aggregates).
3. **No new tenant table, no migration.** Artifacts are generated on demand
   and never persisted — the WO-71 decision-7 precedent ("advisory findings
   are not persisted in this slice"; here: nothing at all is persisted). The
   vault tree exists INSIDE the ZIP, not on disk, so §3.M's backend routing
   (local/SharePoint/FTPS) stays out of scope.
4. **Formula-injection sanitization** via the ONE shared
   `app.core.csv_safety.sanitize_cell` (WO-29/R1 unification) on every
   free-text cell — supplier names, invoice numbers, product groups, entity
   fields, manifest filenames — and deliberately NOT on numeric money cells,
   where a leading `-` is a legitimate negative amount (`csv_safety.py`'s own
   docstring rule).
5. **Missing document bytes fail CLOSED.** R10 guaranteed every resolved
   invoice had a vaulted capture at submission; if the object-store bytes are
   gone at assembly time (`core.storage.StorageError` — a plain `Exception`,
   not an `AppError`), the pack refuses (`code="evidence_document_unavailable"`)
   rather than shipping a silently-incomplete filing bundle.
6. **Money**: every figure is read from the frozen `Numeric(14,2)` columns as
   `Decimal` and summed with `q2` ROUND_HALF_UP (R14, master-context §4.9) —
   nothing is ever recomputed from `FuelTransaction` rows (the frozen lines
   are the authority) and nothing passes through float. Mixed-currency claims
   cannot reach this module (`freeze._sum_lines` refused them at submission);
   the loader still refuses on the same condition defensively
   (`claim_currency_mismatch`) rather than assuming.
7. **Supplier names** resolve via `invoice_id → app.services.invoices.
   get_by_id → vendor_id → app.services.vendors.list_vendors` id-map — never
   a cross-domain model import (`test_boundaries.py::
   test_transport_services_do_not_import_other_domain_models`). After the
   synthetic refusal every line has a non-NULL `invoice_id` by construction
   (`claim_lines.build_claim_lines`: a non-UNMATCHED ref always resolved).
8. **Known gap recorded, not fixed here:** `lock.submit_claim` does not yet
   apply the R3 synthetic block itself (D5's "*then* set_status(engine) which
   applies synthetic/duplicate/document gates" — the synthetic member is
   unwired; `document_gate.py`'s docstring says so explicitly). A claim with
   an UNMATCHED line can therefore currently freeze — and this order's
   builders are the first BLOCKING consumers of `is_synthetic()` anywhere, so
   such a claim cannot produce filing artifacts (exactly Fleet Fuel's
   defence-in-depth: all four surfaces block independently). Wiring the
   submit-side synthetic gate is reported as a follow-up, not smuggled into
   this order's scope.

### Implementation guidance

1. `_load_pack(db, org_id, claim_id)`: module entitlement (`modules.
   is_enabled`, `PermissionError` `module_not_enabled` — the transport-wide
   pattern), org-scoped claim fetch (`NotFoundError` `claim_not_found`,
   §4.4 opaque 404), select lines `WHERE frozen_at IS NOT NULL` ordered
   `(invoice_ref, product_group)`; none → `ConflictError` `claim_not_frozen`;
   any `is_synthetic(ln.invoice_ref, ln.vat_id)` → `ConflictError`
   `synthetic_line_in_pack` naming every offending ref; recompute totals with
   `q2`, mismatch vs frozen header → `ConflictError` `claim_totals_drift`;
   resolve entity (`issuer.get_by_id`), AP invoices (`invoices.get_by_id`
   per distinct id), vendor names (`vendors.list_vendors` map).
2. `_render_workbook(pack) -> bytes`: openpyxl (already pinned, the
   `report_writers.to_xlsx` precedent — lazy import inside the function),
   sheets `Claim` + `Lines`, `sanitize_cell` on free text only, `Decimal`
   money cells written as numbers, TOTAL row from the recomputed `q2` sums.
3. `build_workbook(db, org_id, claim_id) -> bytes` = `_load_pack` +
   `_render_workbook`.
4. `build_evidence_pack(db, org_id, claim_id) -> bytes`: `_load_pack` once;
   ZIP (`zipfile`, in-memory) rooted at `vault_prefix(pack)` =
   `<entity name> <reg no>/<year>/<country>/<period_label>/` (every segment
   `_sanitize_segment`-ed); entries: `claim-workbook.xlsx` (from
   `_render_workbook` over the SAME pack), one entry per distinct vaulted
   capture (`extraction.list_for_invoice` per pack invoice, deduped by
   sha256; bytes via `documents.load(documents.UPLOADS, …)`, `StorageError`
   → `ConflictError` `evidence_document_unavailable`), `manifest.csv`
   (file, sha256, size — `sanitize_cell` on names).
5. Docstrings state why each gate fails CLOSED (master-context §6 — the
   fail-open/fail-closed reasoning is mandatory prose).

### Invariants this order must preserve

- **§4.1/§4.4 (tenancy):** every query org-filtered; cross-tenant claim id →
  opaque 404 (tested). No new table ⇒ RLS set-equality untouched.
- **§4.9/§4.14 (money):** Decimal + `q2` only; no float; no cross-currency
  sum (defensive `claim_currency_mismatch`); figures come from frozen
  columns, never recomputed from transactions.
- **§4.10 (server recomputes totals):** the drift check refuses a frozen
  header that no longer equals its lines.
- **R3 (one predicate):** `claim_pack` imports `claim_gates.is_synthetic`;
  a structural test asserts the module defines no rival predicate.
- **§4.18-adjacent (immutability):** generation is pure read — a submitted
  claim's stored figures are never touched by rendering.
- **ADR-P3 layering:** transport service imports core + own-domain models +
  foreign-domain SERVICES only; `test_boundaries.py` stays green.

### Testing requirements

`backend/tests/transport/test_g2_12_claim_pack.py` — at minimum:
- **Refusals:** draft/unfrozen claim → `claim_not_frozen`; frozen UNMATCHED
  line → `synthetic_line_in_pack` (both artifacts, same code); `INPUT`-in-
  vat_id variant refused; tampered `claim.vat_eur` → `claim_totals_drift`;
  missing object-store bytes → `evidence_document_unavailable`; module
  disabled → `module_not_enabled` (the service-level granted/denied pair —
  route-level role authz ships with the route batch); org B's claim id under
  org A → 404 `claim_not_found`, never 403.
- **Workbook correctness (financial):** line cells equal the frozen Decimal
  figures; TOTAL row equals `claim.vat_eur`/`vat_local` exactly; goods codes
  present; deterministic row order.
- **Injection:** a vendor named with a leading `=`/`+` and an invoice number
  with a leading `=` render quote-prefixed in every free-text cell; numeric
  cells NOT quote-prefixed.
- **Identity (the acceptance):** parse the standalone workbook AND the
  workbook inside the evidence pack — identical `Lines` rows and identical
  totals, cell for cell.
- **Bundle shape:** vault-tree prefix with sanitized segments
  (`period_label` Q-form + Annual form; illegal filesystem chars stripped);
  manifest lists every entry with its real SHA-256; document bytes present
  and byte-identical to what was stored.
- **Structural (R3):** the module calls `claim_gates.is_synthetic` and
  contains no second synthetic predicate (source inspection, the WO-51
  grep-test style).
- **Withdrawn claim** still renders (frozen lines persist — documented
  decision), proving withdraw never mutates frozen lines.
