### Objective and business value

The tenant tax-code catalog (`/tax-codes`), the tenant currency catalog (`/currencies`) and the document registry (`/documents`) are complete, tested APIs with **zero frontend consumption** (`grep -rn "tax-codes\|/currencies\|/documents"` over `frontend/src` finds only `/fx/currencies` — a different surface). The costing masters (departments, cost centers, projects) are a complete *service* with no API and no UI, so the cost-allocation dimensions on invoices and expenses (`app/core/dimensions.py`) remain free-text tags with a master table nobody can populate — `costing.resolve_link_id` can never match, and the Slice-2 dual-read transition (free text → FK links) is stalled at zero masters.

Who stops losing money: a finance lead configuring their workspace today cannot set their VAT rates, their currency list or their cost objects at all — the trial hits ARCH risk **C-6** ("trial users hit the empty half of the product… and conclude it is unfinished") on the very first configuration task. Each of these is a five-minute admin job *if a screen exists* and a support ticket (or a lost trial) if it does not. The documents screen additionally gives the admin the evidence surface auditors ask for first: "show me every original you hold."

### Implementation guidance

1. Backend first: schemas → routes → router registration. Copy the authz commentary style of `routes/tax_codes.py` (why read = `INVOICE_READ`, manage = `SETTINGS_MANAGE`).
2. Audit second: add the `A` names, then `audit.record` immediately before each service commit. Meta: create → `{code, name, ...}`; rename → `{old_name, new_name}`; status/active → `{old, new}`. No money is touched; no masking needed (no bank data in these tables).
3. Run the targeted backend suites (`test_costing.py test_costing_api.py test_tax_codes.py test_currencies.py test_authz_coverage.py test_tenancy_parity.py test_audit*.py`) before starting the SPA.
4. Frontend: follow `Vendors.tsx` (list+modal CRUD, `useQuery`/`useMutation`, `QueryState`) and `Issue.tsx`'s version-carried PATCH pattern. Stale-version 409 → surface `apiError(e)` and refetch.
5. e2e: mock `/api/v1/auth/me`, `/api/v1/modules`, and the four data endpoints with `page.route`; seed `localStorage` token before `page.goto`. One happy path per screen (render list → create → row appears; documents: filter by kind). Keep selectors role-based like `smoke.spec.ts`.
6. `npm run build` + full Playwright locally; full backend suite once, at the end, in the background.
