## G-3 — Tenancy spine (orgs, users, RLS, parity test, composite FKs)

**Effort L (6–9d) · P0 · Depends: G-1, G-2.** Prepend `shared/00_MASTER_CONTEXT.md`.
This is the platform's most important order. Spec: BA_bidit.md §7.1 M1–M4.

### Objective & value
Isolation is the P0 constraint: a cross-tenant leak is a GDPR Art. 33/34 breach and the
end of customer trust. Built here, before any business table exists, every later table
inherits it by construction.

### Scope
IN: Organization/User/Membership models; the three isolation layers; opaque-404
convention; conftest with TWO orgs + role factories. OUT: SSO, invitations, permission
matrix content (G-4), any business entity.

### Steps
1. Models: `organizations` (id uuid, name, status active|suspended, created_at),
   `users` (id, email unique, password_hash argon2), `memberships` (org_id, user_id,
   role; PK(org_id,user_id)). `TenantBase` mixin: `org_id` NOT NULL + composite
   uniqueness `(org_id, id)` so children can FK `(org_id, child_id)->(org_id, id)`.
2. Layer 1 — repository/service discipline: every query filters `org_id == ctx.org_id`.
3. Layer 2 — ORM guard: a `do_orm_execute` listener over a REGISTRY of tenant models;
   any SELECT/UPDATE/DELETE lacking an org_id criterion raises in dev/test, logs+denies
   in prod.
4. Layer 3 — Postgres RLS: per-transaction `SET LOCAL app.current_org = :org` from a
   ContextVar; every tenant table gets `ENABLE ROW LEVEL SECURITY` + policy
   `USING (org_id = current_setting('app.current_org')::uuid)` IN THE SAME MIGRATION
   that creates the table. App connects as a NON-superuser role (RLS applies).
5. Parity CI test (the set-equality gate): introspect live schema for RLS-enabled
   tables == the registry of tenant models — a diff in EITHER direction fails.
6. Opaque 404: one `get_or_404(model, id, ctx)` helper; cross-tenant and nonexistent
   are indistinguishable (never 403).
7. conftest: `org_a`/`org_b`, users per role, `client_as(user)`; a canned
   cross-tenant probe helper for every future test to reuse.

### Acceptance criteria
- [ ] Raw SQL as the app role with org B's GUC returns ZERO org-A rows (tested in the postgres CI job).
- [ ] An unscoped ORM query in tests raises (guard proven).
- [ ] Child row pointing at another org's parent → rejected by the DATABASE (composite FK test).
- [ ] Parity test fails the build when a model is added without a policy (prove by adding a dummy in a scratch commit, then revert).
- [ ] By-id fetch of org-A object as org-B → 404 with the same body as nonexistent.
