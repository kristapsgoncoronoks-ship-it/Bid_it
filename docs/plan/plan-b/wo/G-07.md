## G-7 — File gate + content-addressed object storage

**Effort M (4–6d) · P0 · Depends: G-3, G-6.** Prepend `shared/00_MASTER_CONTEXT.md`.
Spec: BA_bidit.md §7.1 M12.

### Objective & value
Attacker-controlled uploads (invoices, receipts) are the product's front door. One
choke point, fail-closed, before any parser ever sees a byte.

### Steps
1. `app/core/filesec.py`: size cap per context; magic-byte sniff vs per-context
   allowlist (pdf, png/jpeg, xml, csv/xlsx); reject active content (macro formats,
   scripts, HTML); AV seam (clamd if configured — then fail CLOSED on scanner error;
   EICAR always rejected).
2. XML safety: one hardened parser util (defusedxml or lxml with entities/DTD off);
   the ONLY allowed XML entry point (boundary test greps for raw lxml/etree usage).
3. Storage: S3/minio, key `org/{org_id}/sha256/{hash}`; dedupe by digest;
   `documents` table (org_id, sha256, size, declared_mime, sniffed_mime, kind,
   uploaded_by; UNIQUE(org_id, sha256, kind)).
4. Serving: permission-gated endpoint issues short-TTL signed URLs; direct-download
   path sets `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`;
   filename sanitized (RFC 5987), CR/LF stripped.
5. Integrity sweep job (G-6 kind): re-hash sample/all vs recorded sha256; mismatch →
   error-log + metric + audit entry.

### Acceptance criteria
- [ ] EICAR body → 422, never stored. PDF-labeled EXE (magic mismatch) → rejected.
- [ ] XXE probe document → parsed inert, no entity resolution (test with a file:// entity).
- [ ] Org B cannot obtain a signed URL for org A's document (opaque 404).
- [ ] Same bytes uploaded twice → one object, two logical rows where kinds differ.
- [ ] Header-injection filename (`a\r\nSet-Cookie:x.pdf`) served sanitized.

Paste the filesec test-file summary (`pytest tests/test_filesec.py tests/test_documents.py -q`).
