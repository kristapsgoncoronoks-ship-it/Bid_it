## G-8 — AR data model + concurrency-safe numbering

**Effort M (5–7d) · P0 · Depends: G-3, G-4, G-5.** Prepend `shared/00_MASTER_CONTEXT.md`.
Spec: BA_bidit.md §3.2–§3.4 + §7.2 M15. The crown jewel's skeleton.

### Steps
1. Models (all TenantBase): `issuer_profiles` (legal_name, vat_number, reg_no, address
   fields, iban/bic, invoice_prefix, next_number, credit_note_prefix, next_credit_number,
   is_default), `customers` (billing+delivery addresses, vat_number, reg_no, contacts
   JSONB, payment_terms_days, default_currency), `issued_invoices` (issuer_id composite-FK,
   customer_id, lifecycle draft|approved|issued|disputed|written_off|cancelled, number
   NULL until issued, dates, currency, seller_json/buyer_json frozen snapshots, totals
   Money, credited_total, amount_paid, UNIQUE(org_id, number)), `issued_lines`
   (description, qty, unit, unit_price, discount_pct, vat_rate, line_total).
2. Numbering: `issuer.lock(db, org, issuer_id)` = `SELECT … FOR UPDATE` on the issuer
   row; format `{prefix}{year}-{seq:04d}`; separate legal series for credit notes;
   numbers allocated ONLY at issue (drafts have none).
3. THE concurrency test (postgres-marked): 16 async workers, own sessions, each locks
   → sleeps 20ms holding the lock → allocates → inserts. Assert allocated ==
   exactly 1..16. Plus the DB backstop test: duplicate number insert → IntegrityError.
4. Per-issuer independence: two issuers allocate in parallel without contention
   (numbers independent, no cross-blocking beyond row scope).
5. Audit every allocation (G-5).

### Acceptance criteria
- [ ] 16-worker test green on real Postgres in CI (not skipped).
- [ ] Gap-free proof: crash-after-lock-before-commit test → number NOT consumed (allocation and invoice insert are one transaction).
- [ ] Two orgs allocate the same number string without conflict (uniqueness is per-org).
