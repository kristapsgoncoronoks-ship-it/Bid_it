## G-10 — AR outputs: PDF, EN-16931 XML, Factur-X, idempotent delivery

**Effort L (7–10d) · P0 · Depends: G-9. Exit = sellable invoicing.**
Prepend `shared/00_MASTER_CONTEXT.md`. Spec: BA_bidit.md §3.10–§3.11 + §7.2.

### Steps
1. PDF (reportlab or weasyprint — pick one, ADR it): rendered FROM THE STORED ROW ONLY
   (frozen snapshots + lines + computed VAT) — no live joins to mutable masters, so the
   PDF cannot disagree with the DB. Drafts render with a DRAFT watermark and no number.
2. EN-16931 CII XML generator from the same stored data; XXE-safe writer; tax
   categories S/AE/E/Z mapped from the VAT engine; validate against the schematron in
   tests (vendored, offline).
3. Factur-X: embed the XML into the PDF (pikepdf) as `factur-x.xml`; extraction
   round-trip test: embedded XML parses back equal to generated XML.
4. Delivery: send-by-email via a provider seam (mailpit in dev); IDEMPOTENT — once
   `sent_at` is set a repeat send is a no-op returning `already_sent: true` unless
   `resend: true`; `viewed_at` set once via a tracking endpoint (requires sent state).
5. Endpoints: GET pdf (inline|attachment), GET xml, POST send, POST mark-viewed —
   all permission-gated (AR_READ / AR_SEND), opaque-404 cross-tenant, drafts have
   no pdf/xml (409 with reason).
6. Recurring templates + generation (G-6 job): schedule math (monthly/quarterly,
   end-of-month safe via periods.py), occurrence key = UNIQUE(org_id, template_id,
   period) — the generator run twice creates ONE invoice (constraint, not check).

### Acceptance criteria
- [ ] PDF bytes contain the stored number, totals and seller lines (text-extraction assert).
- [ ] Round-trip: generate → embed → extract → byte-equal XML.
- [ ] Send twice without resend → one SMTP message (mailpit inbox assert), second response already_sent.
- [ ] Double generator run for a period → one invoice (IntegrityError absorbed).
- [ ] Cross-tenant GET pdf → 404 opaque.
