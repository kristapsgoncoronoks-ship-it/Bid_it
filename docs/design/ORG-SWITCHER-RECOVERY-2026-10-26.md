# Organization-list recovery — 26 October 2026

This candidate addresses CTX-01 from the [invoice/project follow-up](IMPECCABLE-CONTEXT-FIXES-2026-10-23.md), based on draft PR #79 at `47b28e4`. The existing organization list could fail with a real 429 and leave a static dash without explanation or recovery. This is a scoped Impeccable hardening pass on the existing light financial workspace.

## Resulting behavior and boundaries

Keep the current company from the verified session identity visible while loading or recovering the membership list. A membership-list failure must not invent a current company, select its first entry, or expose stale choices. Explain the read state locally. Offer an explicit **Retry organizations** action that only reads the list, waits for a valid server `Retry-After` deadline, and coalesces duplicate manual retries. When list identity conflicts with the verified session, an explicit **Reload workspace** refreshes the document and identity rather than pretending a list retry resolves it.

The identity provider, expected-identity request guards, server permissions, per-session company selection and rate limiter stay authoritative. A list retry must never post a company switch. Existing successful explicit switching and its full-document reload remain the existing contract. This batch does not add a durable switch command or claim to repair uncertain write outcomes. Legal-entity controls and the default design showcase retain their existing behavior.

No backend, migration, dependency, public API, financial arithmetic, provider, GitHub workflow or deployment change is required. Main and Hostinger are outside this candidate's changes.
