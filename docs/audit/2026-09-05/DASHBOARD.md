## DECISION LOG
- ADR-A1..A6 — see `FINDINGS-AND-BACKLOG.md` §Decision log (retry semantics, dead-letter, savepoint scope, CSP shape, compose overlay semantics, threadpool over async rewrite).
- ADR-A7 (PERF-005): the payables worklist is bounded at 200 soonest-due rows with `items_total`/`truncated` on the wire; the summary figures stay whole-population. Ceiling for ap_aging returned to 4.0 (an 8.0 restatement was made and withdrawn in the same session — recorded in `docs/perf/BASELINE-2026-08-27.md`).
- ADR-A8 (FE-001): the `MutationCache` backstop fires ONLY for mutations without their own `onError`, so no double toasts; `retry` never retries a 4xx.
- ADR-A9 (FE-002): public paths (`/login`, `/accept-invite`, `/verify-email`, `/forgot-password`, `/reset-password`, `/sso/callback`, `/portal/`, `/design`) are exempt from the 401 bounce; `?next=` accepts same-origin relative paths only and never a public page.
- ADR-A10 (FE-008): every delete goes through `useConfirm` (promise-shaped `ConfirmDialog`); `window.confirm` sites left as-is for now (P2 FE-009 sweep). Customers "archive" → "deactivate" because the server soft-deactivates.
- ADR-A11 (PROD-011): "a pending invitation counts" now means not-accepted AND not-expired — a semantic tightening of the onboarding derivation, flagged here as a behaviour change (the docstring already promised "pending").
- ADR-A12 (QA-003): the API contract snapshot lives at `docs/api/openapi.json` (1.3 MB, indent 2 for reviewable diffs); a generated TS client stays P3.
- ADR-A14 (PROD-003): the nav is drawn from the permissions the API serves on every identity response; each item names the permission its destination's ROUTER requires for its primary read (configuration surfaces name `settings.manage`). The SPA keeps a full matrix mirror ONLY as a fallback for a response without `permissions`, and a backend test fails the build if the mirror drifts from `ROLE_PERMISSIONS`. Visible consequence: employees no longer see Upload/Team/Issue (all 403 before); finance managers now see Audit log and Reimbursements; employees now see Cost objects (its router is `invoice.read`).
- ADR-A13 (DB-012): constraint parity compares column-sets, FK actions and CHECK texts, never constraint NAMES (batch_alter_table renames them).
- ADR-A22 (PROD-010): the SPA labels roles by their BUSINESS names (Owner, Administrator, Finance manager, Accountant, Auditor, Read-only, Approver, Employee). Labels only — the stored values (`owner`/`admin`/`user`/`user_free`/…) and `ROLE_PERMISSIONS` are unchanged; a backend test holds the SPA labels, MANUAL §1.2 and the matrix equal (the manual's per-role permission COUNT is mechanical). Flagged as user-visible wording change: a member the Team page called "User" is now "Employee", "User-free" is "Read-only".
- ADR-A23 (PROD-004): the pre-cap warning fires in the last 10 % of the monthly invoice allowance, never fewer than 3 invoices before the cap; it links to `/billing` only for holders of `billing.manage` and otherwise names the workspace owner; a failed usage read renders "couldn't check" rather than nothing. The 402 copy names the owner and Plan & billing — no customer can reach "a platform operator". Product wording, not a limit change.
- ADR-A24 (FE-004/005): `scripts/check-query-errors.mjs` is a ratchet — the 20 pages still rendering a failed read as "no data" are listed by name and the list can only shrink; a fixed page must be removed from it in the same commit and a new offender fails the build. The gate fired once during the batch that introduced it (the Upload page's new usage read).
- ADR-A26 (WO-AH): the due-soon view keeps ALREADY-OVERDUE deadlines on the list, flagged, across refund years (the `claimant_documents.expiring` precedent); terminal claims (paid/withdrawn/rejected) and claims with no deadline never appear; horizon 1–365 days, default 14. Read-only, nothing summed.
- ADR-A27 (WO-AG): F3's `country_requirements` default is a power of attorney and an EMPTY configured set REMOVES the configuration (back to the default) — there is no way to configure "nothing required", because the harvest describes no such country. Readiness is informational: the activation click is never refused on it (test-proven).
- ADR-A28 (WO-AI): the archive export is owner-only (`business_role is OWNER`), the one-time link is an `EmailToken` (hashed, single use, 7 days) that goes by email only — no route ever returns it; requests for the same address are coalesced for an hour so the public form cannot flood an inbox; a record whose bytes are gone is listed as `missing`, never dropped. The public `/archive-export` page answers the same way whatever the address (forgot-password posture).
- ADR-A29 (WO-AJ): the receipt-control run's door is the jobs API (`transport.receipt_control` in `USER_ENQUEUEABLE`), so the permission to queue it is the jobs door's own `settings.manage`, not `vat.write`; the panel says "queued", never "done" (R60 preserved).
- ADR-A30 (BE-011): `GET /payment-runs` is bounded (`limit` default 200, max 500, `offset`) — a wire bound flagged as such; no workspace seen so far approaches it, so the list a client sees is unchanged. The concurrency measurement mode is INFORMATIONAL in CI (printed, never gated on a shared runner; an error under load is the one hard failure) until a datapoint from the real host sets a ceiling.
- ADR-A31 (PERF-016): the service freezes its startup heap (`gc.freeze()`) as the last act of `lifespan`, per worker — the measured alternative was a ~140 ms stop-the-world pass on every read that hydrates a few thousand rows. The growth ceilings are NOT widened: `transport_reliability` stays at 8 and now reads 2.9× held by a measurement of the endpoint. The perf harness measures the frozen configuration because ASGITransport runs no lifespan; it never freezes twice in one process (the seed's garbage would be parked for good) and reclaims that garbage before the stopwatch. The residual ~50 ms pass over post-startup caches is recorded (PERF-017) and NOT tuned away with a threshold — a memory-cost measurement comes first.
- ADR-A32 (P2 batch 3): a parent that is a master row (organisation, vendor, user) may not cascade into a record (audit trail, archive, supplier invoice, expense claim) — those links are RESTRICT, and deleting the parent is an explicit decision about its records first. The six financial state columns are closed sets enforced by CHECK; the migration's pre-flight REFUSES (names table, values, counts) rather than coercing unknown values, with one exact normalisation (`lifecycle='paid'` → `issued`, a derived status the resolver already read that way). Composite tenant links that must detach on a parent delete use Postgres's column-list `SET NULL (column)`; the model keeps the dialect-neutral form and the migration carries the list, because SQLite has no such form and the suite has no delete path. The SQLite migration path changes the same delete rules by batch-mode naming so `alembic check` reads the truth.
- ADR-A33 (P2 batch 4): the cyclic collector's gen-2 threshold is a service setting (`gc_gen2_threshold`, default 100, applied per worker with the heap freeze) because it was measured, not assumed: three shape runs per setting showed the residual ~40 ms pass gone (p95 ratio on the p50 ratio) for +1–3 MB of peak RSS; `GC_GEN2_THRESHOLD=10` restores the interpreter default without a release. The connection pool is NOT changed — measured as a variable (2 / 8 / 20) it moved nothing on any endpoint, so CONC-001 is closed as the dashboard's per-request CPU (PERF-018) rather than tuned with a setting the evidence refuted. Integrity sweeps are size-aware at the route: a count decides between the request and the queue, the limit is an operator setting (`INTEGRITY_SYNC_LIMIT`), and the queued answer is a 202 with the job rather than a 200 with a partial report. The daily scheduler's exclusion is an advisory lock (one worker sweeps, others return 0) layered on the idempotency keys that already made a second sweep harmless — a lock that makes it free, not one the correctness depends on.
- ADR-A25 (R2-A3): in-page controls are gated on `hasPerm(...)` from the served permission list on every page (20 pages); the role-name mirror is only the fallback for an identity response without `permissions`. The server still enforces every one of them — this is what a person SEES, not what they can do.
